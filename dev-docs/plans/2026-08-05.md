# 饼图作为散点（比例点）— 纠正版技术方案

> 数据场景：古植物考古——多个遗址的作物占比（黍/粟），每个遗址一个饼图点，大小 ∝ 总样本量。
> 目标：在 Veusz 中实现"每个散点画一个多色饼"。
> 本方案纠正了先前 AI 生成的错误前提（Veusz 依赖 Matplotlib）。

---

## 0. 关键纠正：Veusz 不是 Matplotlib 架构

之前的方案假设"劫持 Matplotlib 的 `axes.add_patch` / `patches.Wedge`"——**错误**。
Veusz 的渲染后端是**自研 Qt (QPainter)**，不依赖 Matplotlib。相关事实：

- 标记系统在 `veusz/utils/points.py`：`getPointPainterPath` 返回单个 QPainterPath（单填充色）
- `plotMarkers` 支持 `scaling` 数组（每点大小）+ `equalarea`（面积正比 → 半径∝√n）
- 点图是 `veusz/widgets/point.py` 的 PointPlotter
- 因此"散点画多片色块"**不能靠改 marker 系统**（marker 是单路径单色），要靠独立 widget 逐点 `painter.drawPie`

---

## 1. 数据预处理（先决条件，Excel/R 完成）

原始数据是**长格式**（每遗址每作物一行）：
```
遗址名称,年代_calBP,总样本量,作物类别,占比_百分比
圪垯川(半坡),5800,1033,黍,95
圪垯川(半坡),5900,1033,粟,5
```

Veusz 绘图按"每行一个位置"。需**透视成宽格式**（每遗址一行，每作物一列）：
```
遗址,年代,总样本量,黍%,粟%
圪垯川(半坡),5800,1033,95,5
```

**注意原始数据的坑**：
- 同遗址年代不一致（5800 vs 5900）→ 需先归一映射
- 粟=0 的行 → 透视后补 0，饼图要能处理 0% 片（不画该片）

Veusz 本身**无长→宽透视**，需在 Excel/R/pandas 完成。CSV 导入本身支持 float+string 列，导入无障碍。

## 2. 方案：B 的改良版——独立 `proportional-scatter` widget

### 为什么不用 A（自定义 marker）
marker 是"单路径单填充色"，表达不了每点多片。硬塞会绕过整个 marker 系统，得不偿失。

### 为什么是"B 改良版"而非全新裸写
复用 PointPlotter 的成熟骨架，只替换"画标记"这一环：

```
新 widget: ProportionalScatter（继承 PointPlotter 或复制其 addSettings + 渲染骨架）
├── 数据输入（复用 PointPlotter 现有设置）
│   ├── xData, yData              # 位置（年代/占比散点坐标）
│   ├── scalePoints               # 总样本量 → √n 半径（已有！equalarea）
│   └── 新增: wedgeDatasets       # 每个占比一段，如 '黍%', '粟%'（多数据集）
│
├── 渲染（核心改动：替换 plotMarkers 调用）
│   └── _drawProportionalPoints()
│       for 每个点 (x, y):
│           radius = k * sqrt(scalePoints[i])      # 面积正比
│           start = 90°（12点方向）
│           for 每个 wedge 数据集 val:
│               sweep = -2π * (val/100)             # 顺时针
│               painter.drawPie(rect, start*16, sweep*16)  # Qt 用 1/16 度
│               start += sweep
│               # 每个 wedge 用独立颜色（固定色 或 colormap）
│
├── 新增设置
│   ├── wedgeData    (Datasets)   # 各占比数据集
│   ├── wedgeColors  (Colors)     # 每段颜色（或 colormap）
│   ├── pieOutline               # 边框
│   └── showTotal (Bool)          # 是否画 n= 标注
│
└── n= 标注（复用 PointPlotter 的 label/text 机制或 drawText 逐点画）
```

### 复用的 PointPlotter 既有能力（零成本获得）
- ✅ `scalePoints` 数据集 + `newMarkerSizes`/`equalarea` → **半径∝√n 已有**
- ✅ per-point colormap（`Color.points`）
- ✅ 数据集表达式、thinfactor、nanHandling
- ✅ **fork 已加的 CI 功能**（ciMode 等）如果能继承则顺带
- ✅ 数据导入/插件

## 2.5 glyph 模式：饼 / 圆环 / bar 统一为"比例符号"（用户洞察）

**核心洞察**：饼、圆环、条形本质是同一份比例数据在极/笛卡尔坐标的不同投影。
`ProportionalScatter` 用 `glyph` 模式统一：

| glyph | 形式 | 极坐标/笛卡尔 | 绘制 |
|-------|------|-------------|------|
| `pie` | 实心圆环分片 | 极坐标（整圆） | `painter.drawPie`（外径圆片） |
| `donut` | 圆心掏空 | 极坐标（内外圆环） | QPainterPath：外圆 arc → 内圆 arc 反向 → 闭合 |
| `bar` | 每点一个微型堆叠条 | 笛卡尔 | 每点画 N 个矩形（水平或垂直堆叠） |

- **pie/donut** 共享角度分片逻辑（wedge 起始角/sweep/分色），只是 donut 多一个内径孔（`innerRadius` 比例设置，如 0.5 = 半直径）
- **bar glyph** 把每个点画成一个小堆叠条（极→笛卡尔投影），宽度/方向可设
- 数据输入三者完全一致（N 个占比数据集），只换"符号画出"这一环

**设置新增**：
```
glyph       (Choice)  pie | donut | bar
innerRadius (Float)   donut 内径比例 (0-0.95)
barDirection (Choice) horizontal | vertical   (bar glyph 时)
```

这使一个 widget 覆盖 pie/donut/bar 三种表达，符合"极坐标 vs 笛卡尔坐标本质相同"的设计。

## 4. 风险与注意

- Qt `drawPie` 的角度单位是 **1/16 度**（`startAngle*16, spanAngle*16`），别用度数直接传
- 0% 段不画，但角度累计仍要正确（跳过 0 长度 wedge）
- 半径公式 `k*sqrt(n)` 的 k 需要与 markerSize 单位对齐（pt/像素）
- 数据透视正确性是前提（长→宽映射错，饼图比例就错）
- 若要复用 CI 功能需确认 PointPlotter 的 CI 渲染是否适用于比例点（可能不适用，需裁剪）

## 5. 与原计划的差异总结

| 项 | 原计划（错误） | 本方案（正确） |
|----|--------------|--------------|
| 渲染后端 | Matplotlib wedge | **Qt QPainter drawPie** |
| 实现位置 | 改 scatter 底层 | **新独立 widget**（B 改良版） |
| 大小映射 | 自己写 Radius=k√n | **复用 scalePoints+equalarea** |
| 数据格式 | 逗号分隔字符串数据集 | **透视宽格式 + 多 wedge 数据集** |
| 多片色 | patches.Wedge 循环 | **painter.drawPie 逐片 + 独立颜色** |
